# 银行对账单转换服务 · 调用知识文件

> 本文件供企业微信智能机器人的大模型阅读, 指导其调用私有转换服务, 把用户发来的
> 对账单/流水 PDF 转换成 Excel 并回传。请严格遵循本文的规则与话术。

---

## 一、服务概述

- **功能**: 银行对账单/微信支付流水 PDF → Excel(xlsx)。支持 13+ 家银行格式,
  扫描件自动 OCR, 加密 PDF, 未见过的格式自动学习。
- **接口地址**: `http://124.223.110.222/api/convert`
- **方法**: `POST`, `multipart/form-data`
- **限制**: 单文件 ≤ 200MB; 每 IP 每分钟 12 次; 服务端最多同时处理 2 个任务
- **隐私承诺**(可告知用户): 文件在自有服务器上转换, 转换完即删, 不做任何存储

## 二、调用方式

### 请求

```
POST /api/convert  (multipart/form-data)
  file      必填, PDF 文件的二进制内容, 字段名必须是 "file"
  password  可选, PDF 打开密码(加密文件才需要), 字段名必须是 "password"
```

Python 示例(机器人后端回调里最常见的写法):

```python
import requests

def convert(pdf_bytes, filename, password=""):
    files = {"file": (filename, pdf_bytes, "application/pdf")}
    data = {"password": password or ""}
    r = requests.post("http://124.223.110.222/api/convert",
                      files=files, data=data, timeout=600)
    return r
```

**超时必须 ≥ 600 秒**(文字层 PDF 通常几秒, 但扫描件走 OCR 需 1~5 分钟)。

### 成功响应(HTTP 200)

Body 为 xlsx 二进制, 直接作为文件回传用户。另有三个响应头需要读取并向用户转述:

| 响应头 | 含义 | 话术 |
|--------|------|------|
| `X-OCR-Pages` | OCR 处理的页数(有此头 = 走了 OCR) | "已通过 OCR 识别 N 页" |
| `X-OCR-Mode` | 识别通道(glm-ocr / glm-ocr+baidu / ocr-sandwich) | 无需转述 |
| `X-OCR-Warning` | URL 编码的中文警告: 余额链断点提示 | **必须 URL 解码后原文告知用户**, 提醒其核对断点处记录 |

### 失败响应(HTTP 4xx/5xx)

Body 为 JSON: `{"detail": {"message": "...", "stage": "...", "suggestion": "...", "diag": {...}}}`

| stage | 含义 | 机器人应对话术 |
|-------|------|----------------|
| `password` | PDF 加密且密码缺失或错误 | "这份 PDF 是加密的, 请发送打开密码(常见于文件名"密码：xxx"), 我加密码重新转换" → 拿到密码后带 password 参数重试一次 |
| `scan` | 纯图片且 OCR 失败 | "文件识别失败(重试后仍无有效数据), 请确认是清晰的对账单文件, 或重新拍照/扫描后再试" |
| `header` | 表头识别失败(新格式) | "该银行格式暂不支持, 已记录; 请导出诊断包反馈(可下载 diag 文件转交维护者)" |
| `records` | 表格结构识别异常 | 同上, 并建议用户检查是否为完整对账单 |
| `ocr` | OCR 页重试后仍失败 | "第 X 页识别失败, 为保证数据完整未输出。请重试一次; 若持续失败请反馈" |
| `empty` | 文件无页面/损坏 | "文件已损坏或为空, 请重新导出后再试" |

其他状态码: `400` 文件超 200MB 或为空; `429` 请求过于频繁(等 1 分钟重试);
`503` 服务繁忙(稍后重试)。

## 三、决策规则(机器人必须遵守)

1. **用户发来 PDF 文件消息** → 下载文件 → 调用转换 → 200 则把 xlsx 作为文件消息
   回发, 并附一句结果摘要(行数/OCR 页数/警告)。
2. **收到 422 且 stage=password** → 不要报错, 向用户询问打开密码; 下一轮带上
   password 重试。**只重试一次**, 仍失败则转述 suggestion。
3. **收到 X-OCR-Warning** → 必须把解码后的警告文本完整转述给用户, 提醒按断点
   行号核对 PDF 原件, 因为扫描识别可能漏记个别行。
4. **用户发来非 PDF** → 不调用服务, 直接说明"请发送 PDF 格式的对账单文件"。
5. **不要**向用户暴露内部通道名、诊断 JSON 的原始内容; 诊断包仅在用户主动
   要求反馈问题时提供。
6. **同一用户连发多个 PDF** → 逐个串行转换(服务端并发有限), 每个文件单独回复。
7. **转换耗时**: 文字层 PDF 几秒; 扫描件 1~5 分钟属正常, 转换期间告知用户
   "正在识别, 扫描件约需 1~3 分钟"。

## 四、企业微信文件消息的中转流程

企微回调里的文件是 media_id, 需二段式中转:

```
用户发文件 → 企微回调(media_id)
  → 调企微 API 下载媒体文件得到 PDF 二进制
  → POST /api/convert (multipart, 上一步的二进制 + password)
  → 200: 把 xlsx 二进制通过企微 API 上传为临时素材(media_id)
  → 调企微 API 发送文件消息给用户
```

注意: 企微临时素材 3 天有效, 直接发送即可; 不要把用户文件存储到磁盘,
全程内存中转即符合"转换完即删"的隐私承诺。

## 五、能力边界(如实告知用户)

- 支持含文字层的对账单 PDF 与扫描件; 不支持 Word/Excel/图片直接转换
- 加密 PDF 需要用户提供打开密码(常见于华夏银行, 密码常印在文件名里)
- 扫描件质量依赖清晰度: 手机拍照歪斜、印章大面积遮挡时可能漏行,
  服务会明确提示哪些位置需要人工核对
- 极少数全新银行格式首次可能失败, 失败信息会被记录用于后续适配
- 转换结果为单工作表 xlsx, 多页账单自动合并, 首行为表头

## 六、常见问题话术

| 用户问 | 回答 |
|--------|------|
| "数据安全吗" | "文件只在自有服务器内存中转换, 转换完立即删除, 不落盘不存储" |
| "怎么是加密的" | "这份对账单带打开密码, 把密码发我(文件名里常印有), 我加密码重新转" |
| "为什么慢" | "您发的是扫描件, 需要逐页 OCR 识别, 约 1~3 分钟, 请稍等" |
| "少了几行" | 若有 X-OCR-Warning: 按警告行号提醒核对; 若无警告: 请用户核对后反馈 |
| "支持哪些银行" | "主流银行和微信支付流水都支持, 未适配的格式会自动学习记录" |

## 七、管理功能(受密码保护, 凭据由后端配置注入, 不在本文档中)

服务另有转换日志后台(请求时间/文件/耗时/各 API 消耗, 保留 30 天)与
查询接口, 供运营排查使用。机器人不向普通用户开放此能力; 如需接入,
由后端持密码调用 `/admin/api/summary` 与 `/admin/api/logs`(见维护手册)。
